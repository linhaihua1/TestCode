# API 自动化测试平台 · 开发文档

> 面向开发者：技术栈、目录结构、数据模型、核心流程、本地开发与测试。读完可快速上手阅读和修改代码。

---

## 一、技术栈

| 层 | 技术 |
|---|---|
| 前端 | React 19 + TypeScript + Vite + Ant Design 6 + @dnd-kit + @ant-design/plots + SheetJS(xlsx) |
| 后端 | Node.js + TypeScript + Fastify 5 + Prisma 6 |
| 数据库 | SQLite（`server/prisma/dev.db` 单文件） |
| 接口执行 | axios（`server/src/engine/request.ts`） |
| UI 执行 | selenium-webdriver（`server/src/ui-engine/runner.ts`） |
| 测试 | Vitest（前后端，服务端用独立 `test.db`） |

**组织方式**：npm workspaces 单仓库三个子项目 —— `client/`（前端）、`server/`（后端）、`shared/`（共享类型）。

## 二、整体架构

```
浏览器（React 前端）
   │  /api/xxx（axios，自动带 JWT）
   ▼
Node.js 后端（Fastify）
   ├── app.ts       鉴权/权限中间件 + 注册所有路由
   ├── routes/      REST 路由（校验入参、调用引擎/Prisma）
   ├── engine/      接口执行引擎（变量/请求/提取/断言/步骤执行）
   ├── ui-engine/   UI 执行引擎（Selenium 驱动 Chrome）
   ├── audit.ts     审计日志写入
   ├── permissions.ts  RBAC 角色判断
   ├── error-codes.ts  统一错误码
   └── db.ts        Prisma 客户端单例
   ▼
SQLite（dev.db / test.db）
```

## 四、数据模型（`server/prisma/schema.prisma`）

| 实体 | 作用 |
|---|---|
| User | 登录用户（role：admin/member/viewer） |
| Project | 项目（数据隔离） |
| Environment | 环境（baseUrl、变量、请求头） |
| ApiDefinition | 接口定义（方法/路径/请求头/query/body/Mock 配置/tags/moduleId） |
| ApiCase | 接口用例（旧版，断言/提取/stepDefs） |
| Module | 目录（type：case/api，parentId 自关联） |
| CaseInfo | 接口用例（steps 多步骤 JSON、status/priority/tags/version/sortOrder） |
| CaseVersion | 用例版本快照（回退用） |
| CaseReview | 用例评审记录（submit/approve/reject + 意见） |
| DebugRecord | 调试记录（stepResults/extractedVariables） |
| TestTask / TestTaskRun | 测试任务 + 执行报告（caseIds/variables/baseUrl/retryCount/timeout/details） |
| GlobalVariable | 全局变量 |
| AuditLog | 审计日志（action/entityType/before/after） |
| UiTestCase / UiScenario / UiReport | UI 用例/执行计划/报告 |

> 关键关系：`Project` 级联其下所有业务数据；`CaseInfo` 挂 `Module`（用例目录），含 `versions`/`debugRecords`/`reviews`。

## 五、核心业务流程

### 5.1 登录鉴权 + RBAC

```
登录 → auth.ts 校验密码 → signToken 签发 JWT(含 userId/username/role)
前端存 token → axios 拦截器带 Authorization
后端 app.ts preHandler：
  1. 校验 token（verifyToken）
  2. 从 DB 回读用户当前角色（避免旧 token 无 role / 角色变更不生效 / 已删用户）
  3. 权限判断：viewer 只读；/api/users、/api/audit-logs 仅 admin；项目写操作仅 admin
```

### 5.2 用例步骤执行（接口自动化核心）

```
调试/任务执行 → runCaseDebug / runOneCase
  → 加载环境 + 全局 + 任务变量（resolver.buildMergedContext 四级合并）
  → executeCaseSteps（engine/case-executor.ts）
      按 setup→test→teardown 顺序，逐步骤执行：
        request：变量替换 → axios 发请求 → 提取(默认值) → 断言(失败策略 stop 可中断测试段)
        script：JS 沙箱（context.get/set + console.log）
        wait：固定/条件等待
        variable：直接赋值/表达式计算
        controller：IF-ELSE / FOR / WHILE（递归子步骤，WHILE 需 maxLoops）
  → 汇总结果 / 记录 DebugRecord 或 TestTaskRun
```

### 5.3 测试任务执行

```
POST /api/test-tasks/:id/run
  → 读任务 caseIds（有序）+ 环境 + 任务变量 + baseUrl 覆盖 + retryCount + timeout
  → 串行/并行执行各用例（跳过已废弃/已删除用例，SKIP 计入汇总）
  → 生成 TestTaskRun（result/详情/summary）
```

### 5.4 评审

```
POST /api/case-info/:id/review {action: submit|approve|reject, comment}
  → 写 CaseReview（评审人/意见/状态流转）
  → 更新 CaseInfo.status（pending/passed/rejected）
```

### 5.5 UI 执行

```
POST /api/ui-tests/:id/run → runUiSteps（setup+test+teardown 合并）
  → buildDriver 启动 Chrome
  → 逐步骤：open/click/type/assert*/wait（buildLocator 支持 8 种定位）
  → 失败自动截图 → 写 UiReport
```

## 六、本地开发

### 启动

```bash
npm install                      # 安装依赖（自动 prisma generate）
cd server && npx prisma migrate deploy && npm run seed && cd ..   # 初始化库 + 演示数据
npm run dev:server               # 后端（4000）
npm run dev:client               # 前端（5173）
```

浏览器 `http://localhost:5173`，`admin / admin@123` 登录。

### 常用命令

```bash
npm run test                     # 前后端所有测试（服务端用独立 test.db）
npm run build                    # 构建前后端
npm run build -w @api-web/server
npm run build -w @api-web/client
npm run seed -w @api-web/server   # 造演示数据
npm run clean -w @api-web/server  # 清空数据
```

### 数据库变更

修改 `schema.prisma` 后：

```bash
cd server
npx prisma migrate dev --name <迁移名>   # 生成并应用迁移
npx prisma generate                     # 重新生成 Prisma Client
```

> ⚠️ SQLite 下 Prisma 给已有表新增 Json 字段时，迁移 SQL 的 `INSERT..SELECT` 会漏掉新列导致空串损坏（P2023）。需手动在迁移里内联 `'[]'` 默认值（本项目已按此约定处理）。

### 测试约定

- 服务端测试用 `vitest.config.ts` 里的独立 `test.db`，串行执行避免数据冲突。
- 每次改动后跑 `npm run test`，遵循 `AGENTS.md`（改动提交 + 测试通过）。

## 七、权限与错误码

### 权限（RBAC）

| 角色 | 权限 |
|---|---|
| admin | 全部 |
| member | 接口/UI 自动化 + 环境配置（写） |
| viewer | 只读 |

实现：`app.ts` 中间件 + `permissions.ts`（`hasRole`/`isAdmin`）。

### 错误码

统一在 `server/src/error-codes.ts`，响应 `{ code, error, message }`。前端 `getErrorMessage` 会自动带 `[code]` 前缀。详细码表见操作文档「错误码说明」。
