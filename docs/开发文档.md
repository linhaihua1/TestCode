## 第一部分：技术栈与架构约定

### 1.1 技术栈

前端：

- 框架：Vue 3 + TypeScript
- 组件库：Ant Design Vue 4.x
- 状态管理：Pinia
- 构建工具：Vite
- 拖拽库：vuedraggable（基于 SortableJS）
- 代码编辑器：Monaco Editor
- 树组件：基于 Ant Design Vue Tree 二次封装，支持虚拟滚动
- 工程规范：ESLint + Prettier；单测 Vitest + @vue/test-utils

后端：

- 语言：Java 17 / Spring Boot 3.2.x
- 数据库：MySQL 8.0
- ORM：MyBatis-Plus 3.5.x
- 数据库迁移：Flyway（`baseline-on-migrate`，迁移脚本位于 `db/migration/`）
- 对象映射：MapStruct（Entity ↔ DTO/VO）
- 缓存：Redis 7.x
- 消息队列：RabbitMQ（用于任务异步执行）
- 定时任务：Quartz Scheduler（集群模式）
- 对象存储：MinIO（>1MB 请求/响应体转存）
- API 风格：RESTful + springdoc-openapi 自动文档
- 可观测性：Spring Boot Actuator + Micrometer（Prometheus 指标）+ Micrometer Tracing/OpenTelemetry（TraceId 链路追踪、慢 SQL 监控）
- 工程质量：ArchUnit（架构约束测试）+ JaCoCo（覆盖率门槛）

### 1.2 架构约定

- 前后端分离，前端通过 RESTful API 与后端交互
- 分层：Controller → Service → Mapper 严格单向依赖；**Controller 不直接注入 Mapper**，业务逻辑与事务收敛在 Service
- 契约：API 出入参使用 `dto/`（请求）与 `vo/`（响应），经 MapStruct `converter/` 转换，Entity 不直接出入参
- 执行引擎为独立模块，任务通过 RabbitMQ 异步投递，执行机通过心跳注册到资源池
- 所有调试记录、执行报告的请求体/响应体，超过 1MB 时存储到 OSS/MinIO，数据库只存引用路径
- 所有时间字段统一使用 UTC 存储，前端展示时转换为本地时区

## 第三部分：API 接口规范

### 3.1 通用约定

- 基础路径：`/api/v1`（Mock 服务例外，走 `/api/mock`）
- 请求头：`Content-Type: application/json`；`Authorization: Bearer {token}`
- 响应格式统一为：
  - 成功：`{ "code": 0, "message": "ok", "data": { } }`
  - 失败：`{ "code": 错误码, "message": "错误描述", "data": null }`
- 分页响应格式：`{ "code": 0, "message": "ok", "data": { "list": [], "total": 100, ... } }`（统一 `PageResult<T>`）
- HTTP 状态码约定：业务失败返回 400、未登录 401、无权限 403、未找到 404、服务异常 500；**登录失败（1006）返回 HTTP 200 + 业务码**，登录态失效（1002）返回 HTTP 401

### 4.1 变量解析算法

输入：字符串 text、当前执行上下文 context
输出：替换后的字符串

解析规则（伪代码）：

```
function resolveVariables(text, context):
    pattern = /\$\{([a-zA-Z_][a-zA-Z0-9_]*)\}/g
    result = text
    for each match in text.matchAll(pattern):
        varName = match[1]
        value = resolveVariableValue(varName, context)
        if value != null:
            result = result.replace(match[0], value.toString())
        else:
            log.warn("Variable not found: " + varName)
            // 保留原样
    return result

function resolveVariableValue(varName, context):
    // 按优先级查找
    if context.tempVariables.contains(varName):
        return context.tempVariables[varName]
    if context.taskVariables.contains(varName):
        return context.taskVariables[varName]
    if context.environmentVariables.contains(varName):
        return context.environmentVariables[varName]
    if context.globalVariables.contains(varName):
        return context.globalVariables[varName]
    return null
```

嵌套变量解析：先解析内层 ${...}，再解析外层。例如 ${env_${system}}，先解析 ${system} 得到值 test，再解析 ${env_test}。

### 4.2 用例执行流程

```
executeCase(caseId, context):
    // 1. 加载用例及步骤
    case = loadCase(caseId)
    if case.status == DEPRECATED:
        markAsSkipped("用例状态为已废弃")
        return

    // 2. 执行前置步骤
    for step in case.steps.where(position == PRE and enabled):
        result = executeStep(step, context)
        if result.failed and step.failStrategy == STOP:
            executePostSteps(case, context)
            return buildFailedResult(result)

    // 3. 执行测试步骤
    for step in case.steps.where(position == TEST and enabled):
        result = executeStep(step, context)
        if result.failed and step.failStrategy == STOP:
            executePostSteps(case, context)
            return buildFailedResult(result)

    // 4. 执行后置步骤（无论成功失败都执行）
    executePostSteps(case, context)

    // 5. 返回结果
    return buildSuccessResult()
```

### 4.3 断言执行逻辑

```
executeAssertion(assertion, response, context):
    actualValue = extractActualValue(assertion.type, assertion.expression, response)

    switch assertion.type:
        case STATUS_CODE:
            passed = compare(actualValue, assertion.operator, assertion.expectedValue)
        case CONTAINS:
            passed = response.body.contains(assertion.expectedValue)
        case JSONPATH:
            actualValue = jsonPath(response.body, assertion.expression)
            passed = compare(actualValue, assertion.operator, assertion.expectedValue)
        case REGEX:
            pattern = new RegExp(assertion.expression)
            passed = pattern.test(response.body)
        case XPATH:
            actualValue = xpath(response.body, assertion.expression)
            passed = compare(actualValue, assertion.operator, assertion.expectedValue)
        case EMPTY:
            actualValue = jsonPath(response.body, assertion.expression)
            passed = (actualValue == null or actualValue == "")
        case RESPONSE_TIME:
            passed = response.duration <= assertion.expectedValue

    if not passed:
        recordAssertionFailure(assertion.failureMessage, assertion.expectedValue, actualValue)
        if assertion.failStrategy == STOP_CASE:
            throw StopCaseException("断言失败，停止用例执行")
```

### 4.4 流程控制器执行逻辑

IF-ELSE 控制器：

```
executeIfController(controller, context):
    condition = resolveVariables(controller.condition, context)
    if evaluateCondition(condition):
        executeChildSteps(controller.thenSteps, context)
    else if controller.elseSteps != null:
        executeChildSteps(controller.elseSteps, context)
```

FOR 循环控制器：

```
executeForController(controller, context):
    loopCount = controller.loopCount
    loopVariable = controller.loopVariable
    for i in range(loopCount):
        context.setVariable(loopVariable, i)
        executeChildSteps(controller.childSteps, context)
```

WHILE 循环控制器：

```
executeWhileController(controller, context):
    iteration = 0
    maxIterations = controller.maxIterations  // 必填，防止死循环
    while evaluateCondition(controller.condition, context):
        if iteration >= maxIterations:
            log.warn("WHILE 循环达到最大次数，强制退出")
            break
        executeChildSteps(controller.childSteps, context)
        iteration++
```

事务控制器：

```
executeTransactionController(controller, context):
    transactionResult = executeChildSteps(controller.childSteps, context)
    if transactionResult.hasFailure:
        markTransactionAsFailed(controller.name)
    else:
        markTransactionAsSuccess(controller.name)
```

### 4.6 任务执行调度逻辑

```
executeTask(taskId):

    cases = loadCasesByIds(task.caseIds)

    // 过滤：跳过禁用和废弃用例
    executableCases = cases.filter(c => c.status != DEPRECATED and c.enabled)
    skippedCases = cases.filter(c => c.status == DEPRECATED or not c.enabled)
    logSkippedCases(skippedCases)

    // 执行模式
    if task.executeMode == SERIAL:
        for case in executableCases:
            result = executeCaseWithRetry(case, task)
            if result.failed and task.failStrategy == STOP_ALL:
                break
    else:  // PARALLEL
        threadPool = createThreadPool(task.parallelCount)
        for case in executableCases:
            threadPool.submit(() -> executeCaseWithRetry(case, task))
        threadPool.awaitTermination(task.globalTimeout)

    // 生成报告
    report = generateReport(task, results)
    saveReport(report)
    sendNotification(report)
```

```
compareDebugRecords(recordA, recordB):
    differences = []

    // 对比请求差异
    for step in recordA.steps:
        stepB = recordB.steps.find(s => s.id == step.id)
        if stepB == null:
            differences.add({ type: "STEP_REMOVED", stepName: step.name })
        else:
            if step.request != stepB.request:
                differences.add({ type: "REQUEST_CHANGED", stepName: step.name, before: step.request, after: stepB.request })
            if step.response != stepB.response:
                differences.add({ type: "RESPONSE_CHANGED", stepName: step.name, before: step.response, after: stepB.response })
            if step.assertionResults != stepB.assertionResults:
                differences.add({ type: "ASSERTION_CHANGED", stepName: step.name, before: step.assertionResults, after: stepB.assertionResults })
            if step.extractedVariables != stepB.extractedVariables:
                differences.add({ type: "VARIABLE_CHANGED", stepName: step.name, before: step.extractedVariables, after: stepB.extractedVariables })

    return differences
```

## 第七部分：边界条件与异常处理清单

AI 实现时需要覆盖以下边界情况：

变量相关：

- 变量不存在时：日志警告 + 保留原始 ${变量名}（默认行为）
- 嵌套变量超过 5 层：停止解析，日志警告
- 密钥类型变量导出：值显示为 ENCRYPTED
- 删除被引用的变量：返回错误码 2002，列出引用位置

用例相关：

- 删除有子目录的目录：弹窗确认，选择"仅删除目录"或"同步删除子内容"
- 删除有子用例的目录：同上
- 用例名为空：不允许保存，前端提示
- 用例无任何步骤：允许保存，但调试时提示"用例无步骤"
- 复制用例到相同目录：自动在名称后添加"（副本）"
- 版本回退后再次编辑：生成新版本，不回退中丢失

调试相关：

- 调试时变量解析失败：记录警告但继续执行
- 断言失败策略为"停止用例"：停止后续步骤，但后置步骤仍执行
- 后置步骤失败：默认忽略，记录日志
- 提取失败：使用默认值或标记为 null
- 调试记录超过 1MB：截断存储，显示"内容过大已截断"

任务相关：

- 任务包含已废弃用例：跳过并记录
- 任务包含已删除用例：跳过并记录
- 并行执行时共享变量冲突：加锁保护
- 全局超时触发：停止所有执行中的用例，标记为超时失败
- 重试时变量状态：重置该用例的临时变量

Mock 相关：

- Mock 条件匹配不到任何规则：返回默认响应，若无默认响应返回 404
- Mock 响应变量引用不存在：保留原始字符串

回收站相关：

- 还原时原目录已不存在：还原到根目录
- 还原时同名冲突：提示重命名后还原
- 自动清理周期为"不自动清理"：跳过清理任务
