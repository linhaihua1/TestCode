# API 自动化测试平台 · 安装文档（本地开发）

> 本文档说明如何在**本地（Windows）**安装运行，用于开发与调试。
> **Linux 服务器部署请查看《安装文档-Linux.md》**（含一键安装包、systemd + Nginx 等）。

---

## 一、环境要求

- **Node.js ≥ 20**（推荐 20 LTS 或更高）
- **npm**（随 Node 安装）
- **Git**（可选，从仓库拉取代码用）
- **Chrome + chromedriver**（仅 UI 自动化功能需要，接口自动化可跳过）
- **JDK 8+ 与 Apache JMeter**（仅性能测试功能需要；接口/UI 自动化可跳过，详见第四节）

---

## 二、本地安装运行

### 2.1 获取代码

```bash
# 方式一：Git 克隆
git clone <仓库地址> api-web
cd api-web

# 方式二：解压源码包后进入项目根目录
```

### 2.2 安装依赖

```bash
npm install
```

> 首次安装会自动运行 Prisma Client 生成（`prisma generate`）。

### 2.3 配置环境变量（可选）

后端默认值已可用，如需修改，在 `server/.env` 中配置：

```bash
DATABASE_URL="file:./dev.db"   # SQLite 数据库文件路径
PORT=4000                       # 后端监听端口
HOST=0.0.0.0                    # 监听地址（默认 0.0.0.0）
JWT_SECRET=api-web-secret-change-me   # JWT 签名密钥（生产务必修改）
CHROMEDRIVER_PATH=              # chromedriver 路径（可选，UI 自动化用）
JMETER_HOME=                    # JMeter 安装目录（可选；留空则用内置 server/jmeter）
PERF_TIMEOUT_MS=3600000         # 单次压测最长执行时间（毫秒，默认 1 小时）
```

### 2.4 初始化数据库

```bash
cd server
npx prisma migrate deploy     # 应用迁移
npm run seed                  # 造演示数据（admin 账号 + 演示项目 + 演示接口）
cd ..
```

### 2.5 启动

```bash
# 终端 1：后端（4000）
npm run dev:server

# 终端 2：前端（5173）
npm run dev:client
```

浏览器打开 `http://localhost:5173`，默认账号 `admin / admin@123`。

## 三、环境变量说明

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DATABASE_URL` | `file:./dev.db` | SQLite 数据库文件路径（相对 `server` 目录） |
| `PORT` | `4000` | 后端监听端口 |
| `HOST` | `0.0.0.0` | 监听地址；生产用 `127.0.0.1` 仅本机可访问更安全 |
| `JWT_SECRET` | `api-web-secret-change-me` | JWT 签名密钥，**生产环境务必修改** |
| `CHROMEDRIVER_PATH` | 空 | chromedriver 可执行文件路径（UI 自动化用） |
| `JMETER_HOME` | 空 | JMeter 安装目录（其下应有 `bin/ApacheJMeter.jar`）。留空则优先使用内置的 `server/jmeter/`，再回退 PATH |
| `JAVA_HOME` | 空 | JDK 目录；留空则使用 PATH 上的 `java`（性能测试需要 JRE/JDK 8+） |
| `PERF_TIMEOUT_MS` | `3600000` | 单次压测最长执行时间（毫秒），超时强制终止并生成超时报告 |

## 四、外部运行时依赖（可选）

### 4.1 UI 自动化（Chrome + chromedriver）

UI 自动化通过 selenium-webdriver 驱动真实 Chrome 执行，需满足：

1. 安装 **Chrome 浏览器**。
2. 下载与 Chrome 版本匹配的 **chromedriver**。
   - 放在 `server/bin/`（项目 `.gitignore` 已排除，不提交），或
   - 通过 `CHROMEDRIVER_PATH` 环境变量指定路径，或
   - 加入系统 `PATH`。
3. 版本不匹配会导致无法启动浏览器，报错时先核对 Chrome 与 chromedriver 版本。

### 4.2 性能测试（JMeter + JDK）

性能测试把用例转换为标准 `.jmx` 后交给 **JMeter 无界面模式**真实执行，需要 Java 运行时 + JMeter 发行包。

**方式一（推荐）：内置到工程**

下载 JMeter（5.x，本项目按 5.2.1 验证）并解压，把内容放到 `server/jmeter/`，使该目录下存在：

```
server/jmeter/
├── bin/ApacheJMeter.jar     # 启动器（后端以 java -jar 方式调用）
├── bin/jmeter.properties
└── lib/                     # 运行所需依赖
```

`server/jmeter/` 已在 `.gitignore` 中排除（与 `server/bin/` 同策略：随项目存在但不提交），因此只需在部署机器上准备一次。

**方式二：指向已有安装**

```bash
# server/.env 或系统环境变量
JMETER_HOME=/opt/apache-jmeter-5.2.1
```

**运行时查找优先级**：`server/jmeter/`（内置）→ `JMETER_HOME` → `PATH` 上的 `jmeter`。

**Java**：确保 `java` 在 `PATH` 上，或设置 `JAVA_HOME`。JDK/JRE 8 及以上即可（JMeter 5.x 要求 Java 8+）。

**验证是否就绪**：

```bash
curl http://127.0.0.1:4000/api/perf-env -H "Authorization: Bearer <token>"
# { "available": true, "source": "embedded", "home": "...server/jmeter" }
```

进入「性能测试」页面时，标题旁会显示绿色「JMeter 就绪」标签；未就绪时用例的编辑、导入、导出不受影响，只有「执行」不可用。

**第三方插件**：

内置的 JMeter 发行包已带 `jmeter-plugins-manager`、`JMeterPlugins-Standard`、`JMeterPlugins-Extras`，即已支持：阶梯/目标并发线程组、3 Basic Graphs 与 5 Additional Graphs 监听器、Inter-Thread Communication、扩展函数等（平台报告页已用 JTL 原生重绘这些图表，无需打开 GUI）。可用 `GET /api/perf-plugins` 查看各插件 installed / partial / missing。

仍缺的插件按需补装（把 jar 放入 `server/jmeter/lib/ext/` 后重启后端即可）：

| 能力 | 需要 |
|---|---|
| PerfMon 服务器资源监控 | `jpgc-perfmon` 包（采集器 + 测量元件）+ 被监控机上运行 `ServerAgent`（默认 4444 端口） |
| MQTT / AMQP / Dubbo 取样器 | 对应协议插件 jar（Dubbo 用 MeterSphere 官方 `io.metersphere:jmeter-plugins-dubbo`） |

> 注意：平台「创建用例」的结构化编辑器目前只覆盖 HTTP 请求与线程组；含 MQTT/AMQP/Dubbo 等专用取样器的计划需在 JMeter GUI 中编写后通过导入执行（导入仅解析 HTTP 请求与线程组参数）。

> 不使用性能测试功能则无需配置，接口自动化与 UI 自动化完全独立。

## 五、生产部署（Linux）

> 本节为历史说明，最新且完整的 Linux 部署请以《安装文档-Linux.md》为准。

以 Ubuntu/Debian 为例（CentOS 仅安装命令略有差异）。

### 5.1 部署架构

```
                        互联网
                          │
                    ┌─────▼─────┐
                    │   Nginx   │  (80/443)
                    └─────┬─────┘
              ┌───────────┴───────────┐
     静态文件（前端）              反向代理 /api
      client/dist                    │
                          ┌───────────▼───────────┐
                          │  Node.js 后端 (PM2)   │  (4000)
                          │  Fastify + Prisma     │
                          └───────────┬───────────┘
                                      │
                              ┌───────▼───────┐
                              │  SQLite 文件   │
                              │  (dev.db)      │
                              └───────────────┘
```

- **前端**：Vite 构建为纯静态文件，交给 Nginx 托管。
- **后端**：Node.js 进程，用 PM2（或 systemd）守护，监听 4000。
- **数据库**：SQLite 单文件，无需单独安装数据库服务。

### 5.2 安装依赖

```bash
# Node 20（nvm 方式）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install 20 && nvm use 20 && nvm alias default 20

# Nginx
sudo apt-get update && sudo apt-get install -y nginx
sudo systemctl enable nginx

# PM2
sudo npm install -g pm2

# （仅性能测试需要）Java 运行时 + JMeter 发行包
sudo apt-get install -y openjdk-11-jre-headless
# 将 JMeter 内置到工程（推荐，与本机开发一致）：
wget https://archive.apache.org/dist/jmeter/binaries/apache-jmeter-5.2.1.tgz
tar -xzf apache-jmeter-5.2.1.tgz
mkdir -p server/jmeter
cp -r apache-jmeter-5.2.1/bin apache-jmeter-5.2.1/lib server/jmeter/
# 校验：server/jmeter/bin/ApacheJMeter.jar 存在即就绪
# 也可不内置，改为在 server/.env 中设置 JMETER_HOME=/opt/apache-jmeter-5.2.1
# 注意：JMeter 5.2.1 适配 Java 8/11；若使用更高版本 JDK，建议同时升级 JMeter
```

### 5.3 获取代码 + 安装

```bash
cd /opt
sudo mkdir api-web && sudo chown $USER:$USER api-web
git clone <仓库地址> api-web
cd api-web
npm install
```

### 5.4 配置环境变量

```bash
cat > server/.env << 'EOF'
DATABASE_URL="file:./dev.db"
PORT=4000
HOST=127.0.0.1
JWT_SECRET=请改成随机长字符串
EOF
```

> 生产环境 `HOST=127.0.0.1`，后端不直接暴露公网，仅由 Nginx 代理。

### 5.5 初始化数据库

```bash
cd server
npx prisma migrate deploy
npm run seed          # 造初始管理员账号
cd ..
```

### 5.6 构建

```bash
cd /opt/api-web
npm run build -w @api-web/server    # 后端 → server/dist
npm run build -w @api-web/client    # 前端 → client/dist
```

### 5.7 启动后端（PM2）

```bash
cd /opt/api-web/server
pm2 start dist/index.js --name api-web-server
pm2 save
pm2 startup   # 按提示执行输出的命令，设置开机自启
pm2 status    # 查看状态
pm2 logs api-web-server   # 查看日志
```

验证：`curl http://127.0.0.1:4000/api/health` 应返回 `{"status":"ok","service":"api-web-server"}`。

### 5.8 配置 Nginx

```bash
sudo vim /etc/nginx/sites-available/api-web
```

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /opt/api-web/client/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # SPA 路由回退
    }

    location /api/ {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;   # 测试任务执行可能较久，延长超时
    }

    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

启用并重载：

```bash
sudo ln -s /etc/nginx/sites-available/api-web /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
sudo ufw allow 80/tcp    # 防火墙放行（CentOS 用 firewall-cmd）
```

浏览器访问 `http://your-domain.com/` 即可使用。

## 八、常见问题 FAQ

**Q1：curl 后端 health 正常，但通过域名访问 /api 返回 502？**
后端进程没启动或 PM2 崩溃。检查 `pm2 status`、`pm2 logs api-web-server`。

**Q2：前端页面空白 / 刷新后 404？**
Nginx 未配置 `try_files $uri $uri/ /index.html`（SPA 路由回退）。按 5.8 配置。

**Q3：数据库迁移报错（如 P2023）？**
确认 `server/.env` 的 `DATABASE_URL` 路径正确，且以 `server` 为工作目录运行 migrate。若为 Json 字段默认值问题，参考开发文档「数据库变更」约定。

**Q4：登录报错或提示 token 失效？**
`JWT_SECRET` 被修改会导致所有旧 token 失效，需重新登录；务必在部署时设定一次并保持不变。

**Q5：UI 自动化启动 Chrome 失败？**
核对 Chrome 与 chromedriver 版本是否匹配、chromedriver 是否在 `PATH` 或 `CHROMEDRIVER_PATH` 已指定。

**Q6：性能测试无法执行 / 提示「未找到 JMeter 运行时」？**
按 4.2 节准备运行时：确认 `server/jmeter/bin/ApacheJMeter.jar` 存在（或 `JMETER_HOME` 指向有效安装），并确认 `java -version` 可用（JDK/JRE 8+）。改完需重启后端。也可调用 `GET /api/perf-env` 查看后端实际探测到的 `source`（embedded / env / path）与 `home`。

**Q7：如何修改后端端口？**
改 `server/.env` 的 `PORT`，同时改 Nginx `proxy_pass` 端口，然后 `pm2 restart`。

**Q8：如何配置 HTTPS？**
```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

## 九、附：用 systemd 替代 PM2（可选）

```bash
sudo vim /etc/systemd/system/api-web-server.service
```

```ini
[Unit]
Description=API Web Server
After=network.target

[Service]
Type=simple
User=你的用户名
WorkingDirectory=/opt/api-web/server
Environment=DATABASE_URL=file:./dev.db
Environment=PORT=4000
Environment=HOST=127.0.0.1
Environment=JWT_SECRET=请改成随机长字符串
ExecStart=/usr/bin/node dist/index.js
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now api-web-server
sudo systemctl status api-web-server
```
