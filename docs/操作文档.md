# API 自动化测试平台 · 操作文档

> 一个参考 MeterSphere 的接口自动化测试 Web 平台，用于管理接口、编排测试场景、自动执行并生成报告。

---

## 一、平台简介

本平台帮你完成接口测试的完整闭环：

```
接口定义 → 接口用例（断言/提取） → 场景编排 → 执行 → 测试报告
```

- **前端**：React + Ant Design（浏览器界面）
- **后端**：Node.js + Fastify（服务器逻辑）
- **数据库**：SQLite（本地单文件，零配置）

---

## 二、本地启动

### 环境要求
- Node.js v20 及以上（本机已装 v24）

### 启动步骤

**1. 启动后端**（打开一个终端）

```bash
cd C:\Users\Administrator\Desktop\Api-web
npm run dev:server
```

看到 `Server listening at http://127.0.0.1:4000` 即成功。

**2. 启动前端**（再开一个终端）

```bash
cd C:\Users\Administrator\Desktop\Api-web
npm run dev:client
```

看到 `Local: http://localhost:5173/` 即成功。

**3. 打开浏览器**访问

```
http://localhost:5173
```

首次访问会进入**登录页**，使用默认账号登录：`admin / admin@123`（登录后可在「用户管理」中新增/修改账号）。

### 停止服务
在对应终端窗口按 `Ctrl + C`。

### Windows 常见问题
如果 PowerShell 运行 `npm` 报「无法加载 npm.ps1」，先执行一次：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

或改用 `cmd` 命令行运行。

## 三、核心概念

| 名词 | 含义 | 类比 |
|---|---|---|
| **项目** | 一组相关接口/场景的集合 | 一个系统/产品 |
| **环境** | 同一套接口在不同地址下的配置 | dev / test / 生产 |
| **接口定义** | 一个 HTTP 接口的描述（方法、路径、请求头、参数、Body） | Postman 里的一个请求 |
| **接口用例** | 基于接口的「测试用例」，带断言和提取 | 一个测试点 |
| **场景** | 多个用例按顺序编排成一条流程 | 一条业务流程 |
| **断言** | 判断响应是否符合预期 | 检查点 |
| **提取** | 从响应中取出数据，供后续步骤使用 | 传参 |
| **报告** | 一次场景执行的结果记录 | 测试结果 |

**关系**：

```
项目
 ├── 环境（多个）
 ├── 接口定义（多个）
 │     └── 接口用例（多个，含断言/提取）
 └── 场景（多个）
       └── 步骤（多个，每个步骤绑定一个用例）
             └── 执行 → 报告
```

## 四、各功能模块操作说明

### 4.1 项目列表

**入口**：左侧菜单「项目列表」

| 操作 | 说明 |
|---|---|
| 新建项目 | 点击右上角「新建项目」，填名称、描述 |
| 进入 | 点击某项目的「进入」，进入该项目的接口管理页 |
| 编辑 | 修改项目名称/描述 |
| 删除 | 删除项目（会级联删除其下所有环境/接口/场景/报告） |

> 第一次使用：先「新建项目」，再点「进入」开始配置。

---

### 4.2 环境管理

**入口**：进入项目后，左侧菜单「环境管理」

每个环境包含：

- **名称**：如 dev / test / prod
- **Base URL**：接口的基础地址，如 `http://127.0.0.1:8080`（相对路径会自动拼接）
- **变量**：键值对，供接口路径/Body 中的 `${变量}` 使用
- **公共请求头**：该环境下所有请求自动携带的 Header（如 token）

**操作**：新建 / 编辑 / 删除。

> 执行场景前，至少需要一个环境；执行时会选择用哪个环境。

---

### 4.3 接口管理（请求构建器）

**入口**：进入项目后，左侧菜单「接口管理」

**新建接口**：点击右上角「新建接口」，填写：

| 字段 | 说明 |
|---|---|
| 方法 | GET / POST / PUT / PATCH / DELETE / HEAD / OPTIONS |
| 名称 | 接口的显示名 |
| 路径 | 接口路径，支持 `${变量}`，如 `/api/users/${id}`；填完整 URL 则忽略 Base URL |
| 请求头 | 键值对 |
| Query 参数 | URL 查询参数，键值对 |
| 请求体 | JSON 或文本，支持 `${变量}` |
| 描述 | 备注 |

**编辑/删除**：列表每行的「编辑」「删除」。

---

### 4.4 接口用例（断言 / 提取）

**入口**：接口管理页，点某个接口的「用例」按钮，进入用例管理。

每个用例包含：

- **名称**：如「登录成功」「查询成功」
- **断言**：判断响应是否通过（可多条）
- **提取**：从响应取出数据存为变量（供后续步骤引用）

#### 断言配置

| 字段 | 说明 |
|---|---|
| 类型 | 状态码 / JSONPath / 响应头 / 正则 |
| 表达式 | JSONPath 路径、响应头名、或正则（见下） |
| 操作符 | 等于 / 不等于 / 包含 / 不包含 / 匹配正则 / 大于 / 小于 |
| 期望值 | 期望的结果 |

**示例**：

| 类型 | 表达式 | 操作符 | 期望值 | 含义 |
|---|---|---|---|---|
| 状态码 | （留空） | 等于 | 200 | 响应状态码为 200 |
| JSONPath | `$.code` | 等于 | 0 | 响应 JSON 的 code 字段为 0 |
| JSONPath | `$.data.name` | 包含 | 张 | data.name 包含「张」 |
| 响应头 | `Content-Type` | 包含 | json | 响应头含 json |
| 正则 | `"token":"(\w+)"` | 等于 | xxx | 用正则匹配 |

#### 提取配置

| 字段 | 说明 |
|---|---|
| 变量名 | 提取结果存到这个变量（后续用 `${变量名}` 引用） |
| 类型 | JSONPath / 响应头 / 正则 |
| 表达式 | 提取路径 |

**示例**：登录接口返回 `{"token":"abc123","userId":42}`，提取 `token`（JSONPath `$.token`），后续接口的 Header 里就能写 `Authorization: Bearer ${token}`。

### 4.5 场景自动化（编排 + 执行）

**入口**：进入项目后，左侧菜单「场景自动化」

**新建场景**：点「新建场景」，填名称、描述。

**编排步骤**：点场景的「编排」，进入编排页：

1. **添加步骤**：点「添加步骤」，每行下拉选择要绑定的「接口用例」
2. **调整顺序**：用「上移 / 下移」调整执行顺序
3. **删除步骤**：点「删除」
4. **保存步骤**：点右上角「保存步骤」

**执行场景**：

1. 在「执行环境」下拉选择环境
2. 点「执行场景」
3. 下方显示执行报告：每步的通过/失败状态、断言结果

> 执行顺序 = 步骤列表从上到下。前一步「提取」的变量，会自动传给后面所有步骤使用。

---

### 4.6 测试报告

**入口**：进入项目后，左侧菜单「测试报告」

- 列表展示每次执行的：场景名、结果（PASS/FAIL/ERROR）、耗时、执行时间
- 点击行首的展开箭头，查看每个步骤的详细断言结果和失败原因

---

### 4.7 登录与用户管理

**登录**：首次访问平台会跳转到登录页，输入用户名密码登录。默认管理员账号为 `admin / admin@123`。

登录成功后，右上角显示当前用户名，点击可：

- **修改密码**：输入旧密码和新密码，修改后需重新登录
- **退出登录**：清除登录态，返回登录页

**用户管理**（左侧菜单「用户管理」）：

| 操作 | 说明 |
|---|---|
| 新增用户 | 填用户名、密码、角色（管理员 / 查看者） |
| 编辑 | 修改用户名、角色 |
| 改密码 | 重置该用户密码（填新密码即可） |
| 删除 | 删除用户 |

### 4.8 UI 自动化测试

**入口**：进入项目后，左侧菜单「UI 自动化」

基于 Selenium 的浏览器自动化：驱动真实 Chrome 执行「打开页面 / 点击 / 输入 / 断言」等操作，并生成报告。

**新建用例**：点「新建用例」，填名称、Base URL（被测网站的地址）。

**编排步骤**：点用例的「编排」，进入编排页，逐条添加步骤：

| 动作 | 说明 | 需填字段 |
|---|---|---|
| 打开页面 | 打开一个 URL | 目标填 URL（相对路径会自动拼接 Base URL） |
| 点击元素 | 点击某个元素 | 定位方式 + 选择器 |
| 输入文本 | 向输入框输入内容 | 定位方式 + 选择器 + 值（输入内容） |
| 断言元素文本 | 校验元素文本是否包含期望值 | 定位方式 + 选择器 + 值（期望值） |
| 断言元素存在 | 校验元素是否存在 | 定位方式 + 选择器 |
| 断言页面标题 | 校验页面标题 | 值（期望标题） |
| 等待元素出现 | 等待元素加载出现 | 定位方式 + 选择器 + 值（超时秒数，默认 5） |

**元素定位方式**：CSS 选择器 / XPath / ID / Name / 链接文本。

**执行**：点「执行测试」，会启动真实 Chrome 浏览器自动执行，下方显示每步结果；失败/出错步骤会自动截图。

**示例**（打开百度首页并断言标题）：

| 动作 | 目标 | 值 |
|---|---|---|
| 打开页面 | `https://www.baidu.com` | — |
| 断言页面标题 | — | 百度 |

> ⚠️ 执行 UI 测试需要本机安装 Chrome，且 chromedriver 与 Chrome 版本匹配（见部署文档）。

## 五、完整使用流程（示例）

以「登录后查询用户信息」为例：

**1. 建项目**：项目列表 → 新建「示例项目」→ 进入

**2. 建环境**：环境管理 → 新建环境，Base URL 填 `http://127.0.0.1:4000`

**3. 建登录接口**：接口管理 → 新建接口
- 方法 `POST`，名称「登录」，路径 `/login`

**4. 建登录用例**：点登录接口「用例」→ 新建用例「登录成功」
- 断言：状态码 = 200
- 提取：`token` = JSONPath `$.token`；`userId` = JSONPath `$.userId`

**5. 建查询接口**：新建接口
- 方法 `GET`，名称「查询用户」，路径 `/users/${userId}`
- 请求头：`Authorization` = `Bearer ${token}`

**6. 建查询用例**：点查询接口「用例」→ 新建用例「查询成功」
- 断言：状态码 = 200；JSONPath `$.name` = 期望的用户名

**7. 建场景**：场景自动化 → 新建场景「登录查询流程」→ 编排
- 添加步骤 1：绑定「登录成功」
- 添加步骤 2：绑定「查询成功」
- 保存步骤

**8. 执行**：选择环境 → 点「执行场景」→ 查看报告

## 六、变量语法参考

| 语法 | 说明 | 示例 |
|---|---|---|
| `${变量名}` | 引用变量 | `${token}`、`${userId}` |

**变量来源**：
1. **环境变量**（环境管理里配的变量）
2. **提取结果**（场景执行时，上一步提取的值，按执行顺序自动传给后续步骤）

**可用位置**：接口路径、请求头值、Query 参数值、请求体。

**优先级**：后提取的变量覆盖先前的同名变量。

---

## 七、断言操作符一览

| 操作符 | 含义 |
|---|---|
| 等于 (eq) | 实际值 == 期望值 |
| 不等于 (ne) | 实际值 != 期望值 |
| 包含 (contains) | 实际值包含期望值 |
| 不包含 (notContains) | 实际值不包含期望值 |
| 匹配正则 (regex) | 实际值匹配期望的正则 |
| 大于 (gt) | 数值上实际值 > 期望值 |
| 小于 (lt) | 数值上实际值 < 期望值 |

---

## 八、执行结果状态说明

| 状态 | 含义 |
|---|---|
| **PASS** | 全部步骤断言通过 |
| **FAIL** | 存在断言未通过的步骤 |
| **ERROR** | 存在执行出错的步骤（如请求超时、步骤未绑定用例） |

## 九、常见问题 FAQ

**Q1：执行时提示「请先选择执行环境」？**
环境管理里还没有环境，或未在下拉中选择环境。先建一个环境。

**Q2：报告显示 ERROR，某步骤「未绑定接口用例」？**
该步骤没有在下拉里选择用例。回到编排页绑定用例。

**Q3：断言 JSONPath 不生效？**
确认响应是 JSON 格式；JSONPath 写法如 `$.data.list[0].name`（数组用 `[下标]`）。

**Q4：变量没被替换，请求里还是 `${token}`？**
确认变量名拼写一致；且变量来源（环境变量或前面步骤的提取）确实存在。

**Q5：接口路径填了完整 URL 还拼接 Base URL 吗？**
填了 `http://` 开头的完整地址会直接使用，不再拼接 Base URL。
