# API 自动化测试平台 · 操作文档

> 一个参考 MeterSphere 的接口自动化 + UI 自动化 + 性能测试平台。提供 Web 界面管理接口、编写测试用例、编排任务、执行并生成报告。

---

## 一、平台简介

本平台覆盖接口测试、UI 测试与性能测试的完整闭环：

```
接口定义 → 接口用例（断言/提取/多步骤）→ 测试任务 → 执行 → 测试报告
UI 用例（浏览器操作步骤）→ 收集/排序 → 真实 Chrome 执行 → UI 报告
压测用例（并发/时长/请求步骤）→ 自动转 .jmx → 真实 JMeter 执行 → 性能报告
```

- **前端**：React + Ant Design（浏览器界面）
- **后端**：Node.js + Fastify + Prisma
- **数据库**：SQLite（本地单文件，零配置）

## 二、本地启动

### 环境要求

- Node.js ≥ 20（推荐 20/22/24）
- （仅 UI 自动化执行时）本机安装 Chrome 浏览器，且 chromedriver 与 Chrome 版本匹配

### 启动步骤

```bash
# 1. 安装依赖（首次）
npm install

# 2. 初始化数据库 + 演示数据（首次）
cd server && npx prisma migrate deploy && npm run seed && cd ..

# 3. 启动后端（终端 1，监听 4000）
npm run dev:server

# 4. 启动前端（终端 2，监听 5173）
npm run dev:client
```

浏览器访问 `http://localhost:5173`，默认管理员账号：**`admin / admin@123`**。

### Windows 注意事项

若 PowerShell 运行 `npm` 报「无法加载 npm.ps1」，先执行：

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

或改用 cmd 命令行运行。

## 五、接口自动化

### 5.1 接口用例 · 工作台（三栏）

「接口自动化 → 接口用例 → 工作台」是核心编辑界面，分三栏：

| 栏 | 名称 | 功能 |
|---|---|---|
| 左 | 用例库 | 目录树 + 用例管理 |
| 中 | 编写用例 | 用例步骤编辑、调试、评审 |
| 右 | 接口管理 | 接口定义库 |

三栏支持拖拽调整宽度、折叠；每栏右侧有滚动拖拽条，内容超出屏幕时可拖动上下滚动。

#### 用例库（左栏）

- **新建目录**：顶部「新建目录」创建目录；目录节点上的图标支持：新建子目录、新建用例、重命名、删除。
- **新建用例**：目录节点上的「新建用例」图标，在该目录下创建用例。
- **层级**：目录 → 用例。
- **拖拽排序**：拖动用例可在同目录内调整顺序，拖到目录上可移动用例到该目录。
- 用例节点图标：重命名、删除。

#### 编写用例（中栏）

- **用例名称**：顶部输入框。
- **三个页签**：脚本 / 调试记录 / 评审。
- **脚本页签**：前置步骤 / 测试步骤 / 后置步骤三段式，每段标题可点击收起/展开。
- **步骤类型**：
  - **接口请求**：方法、URL（支持 `${变量}`）、请求头、查询参数、请求体、断言、提取。
  - **脚本**：支持 **JavaScript / Python / Java** 三种语言（各带模板）。脚本内用 `context.get('变量名')` 读参数、`context.set('变量名', 值)` 写参数，写入的键即成为后续步骤可引用的参数。
  - **等待**：固定等待（**等待时间以毫秒为单位，可手动输入任意值**）/ 条件等待。
  - **变量赋值**：变量名 + 值（直接赋值 / 表达式计算）。
  - **流程控制器**：IF-ELSE（THEN/ELSE 区域）、FOR 循环、WHILE 循环（需最大循环次数）。IF 的判断方式可选「表达式」或「**自定义代码**」（JavaScript / Python / Java）——代码方式需给保留变量 `__condition__` 赋值作为分支真假，并可同时 `context.set` 提取参数。控制器卡片默认折叠，点 ▼ 展开编辑。
- **步骤添加**：底部「等待 / 脚本 / 流程控制器」三类可**拖拽**到前置/测试/后置任意步骤的前面或后面（拖到卡片上半/下半即插到该步骤前/后，拖到区域空白处则追加到末尾）；点击按钮则直接追加。
- **步骤操作**：
  - 左侧开关：启用/禁用该步骤。
  - 拖拽手柄：拖动排序。
  - 右键菜单：复制 / 粘贴步骤。
  - 删除按钮。
- **拖拽接口生成步骤**：从右侧「接口管理」拖一个接口到前置/测试/后置步骤区，自动生成一条带默认断言的接口请求步骤。
- **自动保存**：步骤/名称等编辑后自动保存（无需手动点保存）。
- **调试**：顶部「调试」打开调试弹窗（选择环境、临时变量、执行方式、全速运行）。
- **评审**：评审页签支持提交评审 / 通过 / 驳回，并留评审记录。

#### 接口管理（右栏）

- **接口列表**：左上角显示请求方式 + 接口名称（超 6 字省略，悬停显示完整名）；右下角编辑 / 删除。
- **新建接口**：方法、名称、路径、请求头、查询参数、请求体、描述、Mock 配置。
- **接口导入**：支持 Swagger/OpenAPI（URL / JSON 文件，含示例与复制）与 Excel 模板（下载模板 + 上传）。
- **Mock**：接口可启用 Mock，通过 `/mock/{接口ID}` 公开访问返回模拟响应。
- 接口项可拖拽到编写用例生成步骤。

### 5.2 测试执行

「接口自动化 → 测试执行」：创建任务、收集用例、手动排序、执行。

- **新建任务 / 删除任务**。
- **收集用例**：从用例库选择用例添加到任务。
- **手动排序**：每个用例行支持 上移 / 下移 / 置顶 / 置尾，按列表顺序（升序）依次执行。
- **执行参数**：任务级变量（键值对），优先级高于环境/全局变量。
- **执行环境**：选择执行环境（使用其变量与 Base URL）。
- **执行机地址**：Base URL 覆盖环境地址，留空则用环境地址。
- **执行模式**：串行 / 并行；**失败重试次数**、**超时时间**。
- 执行结果会记录到「测试报告」。

### 5.3 测试报告

「接口自动化 → 测试报告」：

- 顶部选择测试任务，自动加载其各次执行报告。
- 统计卡片：执行总数 / 通过 / 失败·错误 / 通过率 / 平均耗时。
- 图表：状态分布环形图 + 最近 10 次耗时趋势折线图。
- 报告明细：执行记录列表 + 单次详情（汇总 + 用例明细 + 可展开步骤树）。

## 六、UI 自动化

「UI 自动化」基于 Selenium 驱动真实 Chrome 执行浏览器操作。

- **UI 用例**：新建/编辑/删除用例（名称、描述），点「编排」进入步骤编辑。
- **步骤编辑**：前置步骤 / 测试步骤 / 后置步骤三段式，每段用表格维护步骤（动作、定位方式、目标、值），支持上移/下移/删除。
  - **动作**：用户自定义输入（如 `open` / `click` / `type` / `assertText` / `assertExists` / `assertTitle` / `wait`）。
  - **定位方式**：8 种 —— ID / Name / Class Name / Tag Name / 完整链接文本 / 部分链接文本 / CSS 选择器 / XPath。
- **UI 用例执行**：收集 UI 用例 → 拖拽排序 → 保存为执行计划 → 执行（同一浏览器会话串联）。
- **UI 测试报告**：统计卡片 + 图表 + 报告明细（含失败截图）。

> ⚠️ 执行 UI 测试需本机安装 Chrome，且 chromedriver 与 Chrome 版本匹配。

## 七、性能测试（基于 JMeter）

「性能测试」用 JMeter 做接口压测。平台用**结构化表单**描述压测方案，保存/执行时自动转换为标准 JMeter 测试计划（`.jmx`），因此**导出的文件可直接用 JMeter GUI 打开**，外部编写的 `.jmx` 也能**导入后在平台里继续编辑和执行**。

### 7.1 创建用例

「性能测试 → 创建用例」：左侧为用例列表，**右上角有「导入 JMeter」「导出 JMeter」两个入口**。

- **新建用例**：点「新建用例」打开编辑抽屉。
- **压测配置**（对应 JMeter 线程组）：
  | 配置 | 说明 |
  |---|---|
  | 并发线程数 | 模拟的并发用户数 |
  | Ramp-Up（秒） | 多少秒内把线程全部拉起 |
  | 循环次数 | 每个线程重复执行多少轮 |
  | 持续时长（秒） | **填 0 表示按循环次数**；> 0 表示在该时长内持续压测（此时循环次数失效） |
  | 思考时间（毫秒） | 每轮请求之间的停顿 |
  | 请求出错时 | 继续执行 / 启动下一线程 / 停止当前线程 / 停止整个测试 |
- **自定义变量**：对应 JMeter 的「用户定义变量」。在 URL、请求头、请求体中用 `${变量名}` 引用，替换由 JMeter 在执行时完成。
- **请求步骤**：一个用例可包含多个 HTTP 请求，每个请求可配 名称、方法、URL、请求头、Query 参数、请求体（raw，填写后优先于 Query）、断言（响应码/响应文本 × 等于/包含）、启用开关、上移/下移/删除。
- **执行**：列表行点「执行」真实压测（按时长压测会先弹确认框），完成后弹窗给出关键指标，可一键跳转报告。
- **删除**：软删除，历史报告保留可查。

### 7.2 导入 / 导出 JMeter 格式

| 操作 | 行为 |
|---|---|
| **导入 JMeter**（右上角） | 选择一个或多个 `.jmx`（也支持 `.xml`）。解析测试计划中的**线程组 + HTTP 请求 + 请求头 + 断言 + 固定定时器 + 用户定义变量**，还原为平台用例。若一个计划含多个线程组，会导入**第一个**线程组并明确提示 |
| **导出 JMeter**（右上角） | 未勾选 → 导出全部；勾选 1 个 → 导出该用例的 `.jmx`；勾选多个 → 合并为**一个计划、多个线程组**的 `.jmx` |
| 行内「导出」 | 只导出该用例 |

导入导出不改变数据本身（模型与 `.jmx` 双向转换稳定），因此导出→导入→导出结果一致。

### 7.3 测试报告

「性能测试 → 测试报告」：

- 列表列：用例名称、状态（通过 / 有失败 / 执行失败）、请求数、错误率、平均 RT、P95、TPS、耗时、开始时间。
- 点「详情」查看单次报告：
  - 指标卡：请求总数 / 失败数(错误率) / 平均响应 / P95 / TPS / 总耗时
  - 图表：成功失败分布环形图、响应时间趋势（平均 + 最大）、吞吐量趋势
  - **分接口统计**：每个请求的样本数、错误率、平均/最小/最大、P90/P95/P99、TPS
  - **错误 TOP**：按响应码 + 错误信息聚合的出现次数
- 执行环境异常（如未找到 JMeter）也会生成「执行失败」报告并在列表中悬停可见原因。

> ⚠️ 压测会真实向目标服务发起大量请求，请只在授权的环境上执行，并从较小并发开始加压。

## 十、变量语法

| 语法 | 说明 |
|---|---|
| `${变量名}` | 引用变量，如 `${token}`、`${userId}` |

**变量优先级（从高到低）**：

1. 调试临时变量（调试弹窗里配的临时变量）
2. 任务执行变量（测试任务的「执行参数」）
3. 环境变量（环境管理里配的变量）
4. 全局变量（全局变量页配的变量）

**可用位置**：接口路径、请求头值、查询参数值、请求体、脚本、条件表达式。

**提取变量**：接口请求步骤的「提取」可从响应中取出数据（JSONPath / 响应头 / 正则）存为变量，供后续步骤引用（如登录接口提取 `token`，后续请求头写 `Bearer ${token}`）。

---

## 十一、断言操作符

| 操作符 | 含义 |
|---|---|
| 等于 (eq) | 实际值 == 期望值 |
| 不等于 (ne) | 实际值 != 期望值 |
| 包含 (contains) | 实际值包含期望值 |
| 不包含 (notContains) | 实际值不包含期望值 |
| 匹配正则 (regex) | 实际值匹配期望正则 |
| 大于 (gt) | 实际值 > 期望值 |
| 小于 (lt) | 实际值 < 期望值 |

断言类型：状态码 / JSONPath / 响应头 / 正则。每条断言可配「失败提示」和「失败策略」（失败继续 / 停止用例）。

## 十二、错误码说明

接口错误统一返回 `{ code, error, message }`，常见错误码：

| 错误码 | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 参数校验失败 |
| 1002 | 未登录或 Token 过期 |
| 1003 | 无权限操作 |
| 1004 | 资源不存在 |
| 1005 | 资源名称冲突 |
| 2001 | 变量名不合法 |
| 2002 | 变量被引用，无法删除 |
| 2003 | 用例名称为空 |
| 2004 | 任务名称为空 |
| 2005 | 任务至少需要 1 条用例才能运行 |
| 2006 | 循环控制器未配置最大循环次数 |
| 3001 | Swagger 文档解析失败 |
| 3002 | Excel 导入失败，存在非法行 |
| 3003 | 请求方式不合法 |
| 3004 | URL 格式不合法 |
| 4001 | 调试执行异常 |
| 4002 | 任务执行异常 |
| 4003 | Mock 服务异常 |
| 4004 | 报告生成失败 |

## 十三、完整使用流程（示例）

以「登录后查询用户信息」为例：

1. **选项目**：顶部「当前项目」选择器选项目（或「项目管理」新建）。
2. **配环境**：「环境配置 → 环境管理」新建环境，Base URL 填 `http://127.0.0.1:4000`。
3. **建登录接口**：「接口用例 → 工作台」右栏「接口管理」新建接口：POST `/demo/login`。
4. **建登录用例**：左栏用例库新建目录 → 目录下新建用例 → 中栏拖入登录接口生成步骤，配断言（状态码 200）、提取（`token` = JSONPath `$.token`）。
5. **建查询接口**：新建接口 GET `/demo/users/${userId}`，请求头 `Authorization = Bearer ${token}`。
6. **建查询用例**：新建用例拖入查询接口，配断言（状态码 200）。
7. **建任务执行**：「测试执行」新建任务，收集登录、查询两个用例（按顺序），选环境，点「执行」。
8. **看报告**：「测试报告」查看本次执行结果与明细。

## 十四、常见问题 FAQ

**Q1：报告页面没有数据？**
测试执行完成后再进入「测试报告」，或页面顶部选择对应任务；若从侧边栏进入会自动选中第一个任务。

**Q2：变量没被替换，请求里还是 `${token}`？**
确认变量名拼写一致，且变量来源（提取/环境/全局）确实存在；未找到时默认保留原样。

**Q3：新建目录提示 1003 无权限？**
当前账号是「查看者」，只读无写权限；请用成员/管理员账号，或让管理员调整角色。

**Q4：接口名称显示不完整？**
名称超 6 字会省略显示，鼠标悬停到名称上会弹出完整名称。

**Q5：UI 测试执行失败 / 找不到浏览器？**
确认本机已装 Chrome，且 chromedriver 与 Chrome 版本匹配（见安装文档）。

**Q6：性能测试提示「未找到 JMeter 运行时」？**
压测引擎内置在 `server/jmeter/` 目录（不随 Git 提交）。若该目录不存在，请下载 JMeter 并解压，使其存在 `server/jmeter/bin/ApacheJMeter.jar`；或设置环境变量 `JMETER_HOME` 指向已有安装后重启后端。用例的编辑与导入导出不受影响，只有「执行」需要运行时。页面标题旁的绿色「JMeter 就绪」标签表示已检测到。

**Q7：压测报告是「执行失败」且没有指标？**
展开详情可见具体原因，常见为：目标地址不可达、URL 里 `${变量}` 未在自定义变量中定义、或用例没有任何启用的请求步骤。可先点行内「导出」拿到 `.jmx`，用 JMeter GUI 打开本地调试后再导入。

**Q8：导入外部 `.jmx` 后请求数对不上？**
平台按「一个用例 = 一个线程组」建模，含多个线程组的计划只导入第一个（导入结果会提示线程组数量）；JMeter 的高级元件（CSV 数据文件、逻辑控制器、后端监听器等）暂不参与转换，仅保留线程组、HTTP 请求、请求头、断言、定时器与用户定义变量。
