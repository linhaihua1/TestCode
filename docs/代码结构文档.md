# API 自动化测试平台 · 代码结构文档（新手入门）

> 本文档面向**第一次接触这个项目的新人**。读完它，你应该能理解整个项目的目录结构、每个文件是干什么的、以及代码是怎么流转起来的，从而能够快速上手阅读和修改代码。

---

## 一、这个项目是做什么的

这是一个**接口自动化测试 + UI 自动化测试平台**（参考 MeterSphere、Selenium 的设计思路），提供 Web 界面来管理测试、执行测试、查看报告。

它能做两件事：

1. **接口（API）自动化**：管理接口定义 → 编写接口用例（含断言、变量提取）→ 编排成场景 → 执行 → 出报告
2. **UI 自动化**：编写 UI 用例（浏览器操作步骤）→ 收集用例、拖拽排序 → 用真实 Chrome 执行 → 出报告

外加**登录认证**和**用户管理**。

---

## 二、技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | React 19 + TypeScript + Vite + Ant Design | 浏览器界面 |
| 后端 | Node.js + TypeScript + Fastify | Web 服务 + 执行引擎 |
| 数据库 | SQLite + Prisma ORM | 本地单文件数据库，零配置 |
| 接口执行 | axios | 发送 HTTP 请求 |
| UI 执行 | selenium-webdriver | 驱动真实 Chrome 浏览器 |
| 测试 | Vitest | 前后端单元/集成测试 |
| 图表 | @ant-design/plots | 报告图表化 |

**一句话总结**：前后端都是 TypeScript，通过 REST API（`/api/...`）通信，数据库用 SQLite 文件。

---

## 三、整体架构

```
浏览器（React 前端）
   │  通过 /api/xxx 发 HTTP 请求
   ▼
Node.js 后端（Fastify）
   ├── 路由层（routes/）     接收请求、校验、调用引擎
   ├── 执行引擎（engine/）   真正的业务逻辑
   │     ├── 接口引擎：发请求 → 提取 → 断言
   │     └── UI 引擎：驱动 Chrome → 操作 → 断言
   ├── 数据层（Prisma）      读写 SQLite 数据库
   ▼
SQLite 数据库（dev.db 文件）
```

**三个子项目**（用 npm workspaces 组织在一个仓库里）：

- `client/` —— 前端（浏览器里跑）
- `server/` —— 后端（Node 里跑）
- `shared/` —— 前后端共用的 TypeScript 类型定义

## 五、核心概念与数据模型

数据模型定义在 `server/prisma/schema.prisma`，主要实体如下：

| 实体 | 作用 | 类比 |
|---|---|---|
| User | 登录用户 | 账号 |
| Project | 项目（隔离数据） | 一个系统/产品 |
| Environment | 环境（dev/test 的地址、变量、请求头） | 环境配置 |
| ApiDefinition | 接口定义（方法、路径、请求头、Body） | Postman 的一个请求 |
| ApiCase | 接口用例（断言 + 提取 + 多步骤） | 一个测试点 |
| Scenario / ScenarioStep | 场景（组合多个用例按顺序执行） | 一条业务流程 |
| Report / ReportDetail | 接口执行报告 | 测试结果 |
| UiTestCase | UI 用例（前置/测试/后置步骤） | 浏览器操作流程 |
| UiScenario / UiScenarioStep | UI 执行计划（组合多个 UI 用例） | UI 业务流程 |
| UiReport | UI 执行报告 | UI 测试结果 |

**实体关系**：

```
User（登录用户）
Project（项目）
 ├── Environment（环境）
 ├── ApiDefinition（接口）
 │     └── ApiCase（用例，含断言/提取/多步骤）
 ├── Scenario（场景）→ ScenarioStep（步骤，引用 ApiCase）
 ├── Report（接口报告）→ ReportDetail（步骤明细）
 ├── UiTestCase（UI 用例）
 ├── UiScenario（UI 执行计划）→ UiScenarioStep（引用 UiTestCase）
 └── UiReport（UI 报告）
```

## 六、核心业务流程

### 6.1 登录认证流程

```
前端 LoginPage 输入用户名密码
  → POST /api/auth/login（auth.ts 路由）
  → 校验密码（auth.ts 的 bcrypt 对比）
  → 签发 JWT token（auth.ts 的 signToken）
  → 返回 token + 用户信息
前端把 token 存 localStorage（api/auth.ts）
  → 之后每次请求，axios 拦截器自动带 Authorization 头（api/client.ts）
后端 app.ts 的鉴权中间件验证 token
  → 通过则放行，失败则返回 401
```

### 6.2 接口测试执行流程（核心）

```
用户在场景编排页点「执行」
  → POST /api/scenarios/:id/run（scenarios.ts）
  → 调用 runner.ts 的 runScenario
  → 加载场景步骤 + 环境（baseUrl、变量、请求头）
  → 逐步执行每个步骤：
     1. variables.ts 替换变量（${token} → 实际值）
     2. request.ts 发送 HTTP 请求
     3. extract.ts 提取响应数据，写入上下文（供后续步骤用）
     4. assert.ts 判断断言是否通过
  → 汇总结果，写入 Report + ReportDetail
  → 返回报告，前端展示
```

### 6.3 UI 测试执行流程

```
用户在 UI 用例执行页收集用例、拖拽排序、点「执行」
  → POST /api/projects/:projectId/ui-execute（ui-scenarios.ts）
  → 按顺序加载 UI 用例（含前置/测试/后置步骤）
  → 调用 ui-engine/runner.ts 的 runUiScenario
  → 启动一个 Chrome（同一个浏览器会话）
  → 逐个用例、逐步执行（打开页面/点击/输入/断言）
  → 失败时自动截图
  → 汇总结果，写入 UiReport
  → 返回报告，前端展示
```

## 八、本地开发运行

### 前提
- Node.js ≥ 20（本机已装 v24）
- 已执行过 `npm install`（依赖已装好）

### 启动

```bash
# 终端 1：启动后端（4000 端口）
npm run dev:server

# 终端 2：启动前端（5173 端口）
npm run dev:client
```

浏览器打开 http://localhost:5173，用 `admin / admin@123` 登录。

### 常用命令

```bash
npm run test            # 跑前后端所有测试
npm run build           # 构建前后端
npm run seed -w @api-web/server    # 造演示数据
npm run clean -w @api-web/server   # 清空测试数据
```

### Windows 注意事项
- PowerShell 运行 `npm` 报「无法加载 npm.ps1」时，先执行 `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`，或改用 cmd。
- UI 自动化需要 `server/bin/chromedriver.exe`（已下载，不提交 git），且版本需与 Chrome 匹配。

## 九、关键术语表

| 术语 | 含义 |
|---|---|
| 接口定义 | 一个 HTTP 接口的描述（方法、路径、请求头、Body） |
| 接口用例 | 基于接口的测试用例，含断言和提取 |
| 断言 | 判断响应是否符合预期（如状态码=200） |
| 提取 | 从响应中取出数据（如 token），存为变量供后续步骤用 |
| 场景 | 多个用例按顺序编排成的流程 |
| 环境 | 同一套接口在不同地址下的配置（dev/test） |
| 变量 | `${变量名}` 形式，来自环境变量或上一步的提取 |
| UI 用例 | 浏览器操作的步骤序列（打开/点击/输入/断言） |
| 前置/测试/后置 | UI 用例的三段式步骤（对应 Pytest 的 setup/test/teardown） |
| 执行计划 | 收集 UI 用例 + 顺序，用于批量执行 |
| JWT | 登录凭证，前端每次请求携带它证明身份 |

## 十、给新手的最后建议

1. **先跑起来，再读代码**：界面操作一遍，对照代码，理解最快。
2. **抓主线**：先理解「接口测试怎么跑」（routes → engine → 报告），UI 自动化是同样的套路。
3. **改小步、勤提交**：每次改动后跑测试（`npm run test`）和提交 git，遵循 `AGENTS.md` 的规范。
4. **不确定就问**：代码里大部分文件都有中文注释，遇到看不懂的模块，看文件开头的注释说明。
